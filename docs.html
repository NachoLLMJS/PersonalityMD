PRODUCT PRINCIPLES

WHAT THE PRODUCT IS DESIGNED TO DO

HIDE INFRASTRUCTURE COMPLEXITY

Users describe the influencer inside Personality.md while the application translates their choices into an IMD compatible request

USE REAL NETWORK DATA

The Explorer displays public jobs returned by IMD and never presents invented objectives as live work

FAIL CLOSED

Customer image upload is omitted and unavailable provider operations remain blocked instead of showing fictional success

MAINTAIN IDENTITY CONSISTENCY

Every generated image and video request includes the selected appearance voice audience values and boundaries

SEPARATE DESIGN FROM PAYMENT

Users can design and validate a personality before any paid admission flow exists

DISCLOSE SYNTHETIC MEDIA

The product treats virtual influencers as AI generated identities and does not present them as real people

FREE PRECHECK

VALIDATION

VALIDATE WITH LIVE IMD sends the composed request to the live IMD planner without payment

The response can contain a proposed plan facts blockers and suggestions

LOADING

The request is being checked by the upstream planner

SUCCESS

The plan contains no blockers and quote creation can be enabled

ERROR

The request failed transport validation or returned one or more blockers

CHANGED

A form edit makes the earlier validation stale and quote creation is disabled

A successful check does not mean a job exists and does not guarantee that future paid work will complete successfully

REAL PAID ADMISSION

QUOTES AND PAYMENT

CREATE IMD QUOTE generates a fresh UUID request key and sends the validated action and input to IMD

The returned order is real but remains unpaid until the user reviews the exact live price network asset recipient and expiry

Authentication

The browser generates a random 32 byte token encoded as 64 hexadecimal characters and stores it in session storage The same-origin bridge forwards it as a Bearer credential and uses the same token to recover order status

Wallet sequence

  1. Connect an injected Ethereum wallet after an explicit click
  2. Switch to Ethereum Mainnet when required
  3. Read the wallet allowance granted to the official Permit2 contract
  4. Request a reusable IMD token approval only when the allowance is insufficient
  5. Request the x402 v2 challenge for the saved order
  6. Sign the Permit2 payment authorization
  7. Sign the EIP-712 QuoteApproval binding the exact payment payload to the exact IMD quote
  8. Submit both signatures through the same origin bridge
  9. Poll the saved order until it is admitted failed or expired
EXPLICIT APPROVAL

Personality.md never pays on page load Quote creation does not charge anything and every token approval payment signature and quote signature requires a visible wallet confirmation

LIVE TERMS

The current job price is read from each IMD quote rather than hard coded The interface displays the token amount Ethereum Mainnet asset recipient order ID and expiry before enabling payment

A successful payment purchases admission to IMD It does not guarantee that the generated work will complete or satisfy every creative expectation

HIGGSFIELD REFERENCES

IMAGE + MOTION UPLOADS

The HIGGSFIELD workspace accepts one JPEG JPG PNG WEBP or GIF identity image up to 15 MB and one MP4 motion reference up to 50 MB and five seconds

The browser previews local files only after selection The server validates file type size and MP4 duration before issuing restricted direct upload tickets

The Higgsfield credential remains server side and is never returned to the browser committed to the repository or written into public Vite variables

The independent SWARM Creator still has no generic IMD attachment route Its original Build Hairstyle and Heritage selectors continue to send text values in the IMD objective

REAL OUTPUTS ONLY

The result cards remain hidden until Higgsfield returns a real HTTPS video URL and the fairlaunch remains locked until that result exists

EXPLICIT CONSENT

WALLET

The site does not request accounts during initial page load

CONNECT calls eth_requestAccounts only after the user presses the button

After connection the header displays a shortened public address

The wallet can be asked to switch to Ethereum Mainnet and can display a separate Permit2 approval transaction when the IMD allowance is insufficient

The paid flow then requests one x402 Permit2 payment signature and one EIP-712 quote approval signature from the same wallet

No private key or seed phrase is requested stored transmitted or exposed by Personality.md

If no injected wallet exists the UI reports that no browser wallet was detected

SERVER BRIDGE CONTRACT

SERVER API

GET /api/imd/jobs

GET /api/imd/jobs?limit=60&exclude=oracle

Forwards a bounded public job request to IMD with a configured maximum limit of 100

POST /api/imd/check

{ "action": "job.open", "input": { "objective": "...", "skill": "create-video", "outputs": [] } }

Forwards the proposed body to the free IMD request checker

POST /api/imd/quote

{ "action": "job.open", "input": { ... }, "requestKey": "UUID" }

Requires x-personality-request-token containing exactly 64 hexadecimal characters The bridge forwards it as an Authorization Bearer token

POST /api/imd/orders/:id/submit

Without a payment header this route returns the live x402 challenge With PAYMENT-SIGNATURE and a quoteSignature body it forwards the signed payment and admission request to IMD

GET /api/imd/orders/:id

Reads the private saved order using the same client token and returns quoted payment pending admission pending admitted payment failed or expired state

GET /api/imd/capabilities

Reads enabled actions live prices network asset recipient limits and payment protocol configuration from IMD

Bridge failure behavior

  • Unknown bridge routes return 404
  • Invalid request tokens return 401
  • Upstream transport failures return 502
  • Upstream status and JSON bodies are preserved where possible
  • Responses use no store cache headers

COMMON QUESTIONS

FAQ

IS PERSONALITY.MD AN OFFICIAL IMD PRODUCT

No It is an independent application concept using IMD public data and request APIs

DOES VALIDATION COST MONEY

No The current check route is used before quote creation and does not perform payment

DOES CREATE IMD QUOTE START A JOB

No It saves a real unpaid order The user must then review the terms approve Permit2 when required sign the payment and sign the quote approval

WHEN DOES IMD CHARGE THE WALLET

Only after the user presses the payment control and confirms the required wallet prompts Quote creation and validation do not charge

CAN I UPLOAD REFERENCE IMAGES

Yes in the HIGGSFIELD workspace after holder verification The independent SWARM request builder still has no generic IMD attachment route

DOES HIGGSFIELD AUTOMATICALLY LAUNCH A TOKEN

No Generation and fairlaunch are separate A real result unlocks the native SWARM form but CHECK quote payment and wallet confirmation remain explicit steps

DOES CHECK COST MONEY

No CHECK calls the live IMD planner without approval signature or payment

ARE THE SELECTOR IMAGES FROM HIGGSFIELD

No All 21 selector images are original assets generated for Personality.md

CAN THE SITE PUBLISH TO SOCIAL NETWORKS

No Social operation is part of the planned product model but is not implemented

DOES CONNECT SPEND FUNDS

No CONNECT requests account access only Spending requires the later Permit2 approval and payment confirmations

WHY DOES THE TERMINAL SAY WRONG COMMAND

The terminal is a decorative explanation surface Influencer creation belongs in the Creator Studio

CAN THIS BE DEPLOYED AS A STATIC SITE

The pages build statically while Vercel Functions provide the restricted same origin Higgsfield and IMD production bridges
